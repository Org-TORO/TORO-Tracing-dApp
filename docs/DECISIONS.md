## 2026-09-26 — Landing page becomes a story, not a brochure

**Decision:** Rebuild `/` as scroll chapters following one real lot (TORO-01):
The Can → The Catch → The Factory → The Proof → Your Turn → Epilogue.
Remove the "Why Toro" feature-card grid, the stats bar, and full sections for
roadmap/achievements/team (compressed into an epilogue).

**Rationale:** The old page followed the generic SaaS template (hero + stats +
4 cards + video + awards + roadmap + team) and read as "AI/template UI".
Storytelling through the product's own on-chain journey is both more
distinctive and more persuasive — the blockchain becomes the plot device.
Full brief: `docs/LANDING-REDESIGN.md`.

**Consequences:** Data on the landing page must come from `traceIndex.json`
(TORO-01), not hardcoded marketing copy, so the story stays true after
re-indexing. Fonts: Fraunces (display) + JetBrains Mono (chain data) via
Google Fonts `<link>` (matches existing font-awesome CDN pattern; avoids
next/font build-time fetches).

## (Pre-2026-09-26, inferred from code/docs)

- **D: Port EVM ToroRegistry to Solana Anchor.** Same lifecycle, roles, and
  event shapes as the EVM contract. Rationale: team already had EVM design;
  the seed script ports the Solidity demo scripts 1:1 (same payloads).
- **D: Event-only rich data.** Rich trace fields (species, temps, certs) are
  abi-encoded blobs in events, never in accounts. Rationale: Solana rent cost;
  indexers reconstruct history; EVM parity.
- **D: Roles as existence-marker PDAs.** `Role` account exists = authorized,
  verified by seed derivation. Revocation = close account (rent refund).
- **D: Static JSON index instead of backend.** `traceIndex.json` generated by
  `ui/scripts/indexer-solana.ts`. Rationale: no backend yet; Vercel-friendly;
  a live indexer is future work.
- **D: Authority can bypass all roles** (mirrors EVM `onlyFactorySigner` etc.
  where authority is implicitly allowed). Fine for demo; flag for production.
- **D: Input batches are not consumed** when a lot is created. They remain at
  Manufacturing; the lot stores their PDA addresses (`input_batches[16]`).
